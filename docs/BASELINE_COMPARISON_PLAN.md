# 相位优化对比算法与实施计划

状态：首版已实现。算法统一放在 `src/baselines/<algorithm>/`，由顶层 `algorithm` 配置选择；统一 evaluator、预算计数和结果格式已接入。

## 1. 对比目标

在相同阵列、介质、障碍物、边界条件和阵元幅值下，比较不同方法得到的相位与声场：

```text
A u(phi) = B exp(i phi)
G = A^(-1) B
u(phi) = G exp(i phi)
```

主问题是固定场景下的相位优化，不是障碍物反演，也不是神经网络对 PDE 求解器的替代。

希望回答：

1. 相同计算预算下，谁能取得更低损失、更强焦点和更低旁瓣？
2. 达到相同声场质量，需要多少次场评估、多少时间？
3. 当目标点、边界或障碍物变化时，各方法需要付出多少额外成本？
4. 强化学习经过多任务训练后，能否以少量交互或一次推理获得有竞争力的结果？
5. 加入噪声或模型误差后，各方法的性能是否稳定？

不预设我们的算法在所有指标上都最好。解析方法、无梯度搜索和强化学习的能力与信息条件不同，需要分组解释结果。

## 2. 算法清单

| 方法 ID | 算法 | 使用的信息 | 实现安排 |
|---|---|---|---|
| `geometric` | 传统几何相位 | 阵元与目标位置、背景波数 | 首批，封装现有实现 |
| `response_alignment` | 真实响应相位对齐 | G 在目标点处的复响应 | 首批，封装现有实现 |
| `gabs` | 贪心逐阵元相位搜索 | 候选相位的标量损失 | 首批，新增 |
| `spsa` | 同时扰动随机近似 | 正负扰动处的标量损失 | 首批，新增 |
| `sac` | Soft Actor-Critic | 环境观测、动作与奖励 | 首批，传统搜索稳定后新增 |
| `ours_lbfgsb` | 响应基解析 VJP + L-BFGS-B | 已知模型 G、解析梯度 | 主比较方法，适配现有实现 |
| `ours_adam` | 响应基解析 VJP + Adam | 已知模型 G、解析梯度 | 优化器消融，适配现有实现 |
| `ppo` | Proximal Policy Optimization | 与 SAC 相同的观测和奖励 | 第二批，新增 |
| `cmaes` | CMA-ES 进化优化 | 种群候选的标量损失 | 第二批，可选扩展 |

标准高斯过程贝叶斯优化暂不列为首批：当前 12×12 阵列有 144 个连续相位变量，直接在此维度上使用常规 GP-BO 不合适。若以后引入低维相位基或局部 BO，需要单独说明参数化和搜索预算。

### 2.1 几何相位 `geometric`

- 单目标按自由空间传播距离补偿相位；多目标复用当前几何复场叠加规则。
- 对应 `TransducerArray.compute_geometric_phases()`。
- 相位由几何公式产生，但评估必须使用当前实际场景的 G，包含障碍物与反射边界。
- 不迭代优化旁瓣，用作物理模型简化基线。

### 2.2 响应对齐 `response_alignment`

单目标：

```text
phi_r = -arg(G[t, r]) mod 2*pi
```

对于固定阵元幅值、连续相位、仅最大化单点振幅的任务，此法达到三角不等式上界：

```text
max_phi |u_t| = sum_r |G[t, r]|
```

- 对应现有 `PhaseOnlyOptimizer._response_focus_phases()`；后续应提取为可复用的公共函数，避免复制公式。
- 当前多目标形式使用 `arg(sum_k conj(G[t_k, r]))`，这是对齐启发式，不具有一般的多目标全局最优保证。
- 不带背景惩罚的单点振幅最大化应作为正确性测试，而非宣称我们能超过响应对齐的实验。
- 主性能实验使用旁瓣抑制、多目标或完整目标场匹配，评估迭代优化的实际价值。

### 2.3 贪心相位搜索 `gabs`

- 固定其他阵元，对第 r 个阵元枚举 K 个候选相位，选择损失最低者，再处理下一阵元。
- 候选点初版采用 `[0, 2*pi)` 的均匀网格，并保留当前相位作为候选，防止无噪声情况下被迫退化。
- 一个完整 sweep 约需 `M*K` 次候选评估；实际次数由统一计数器记录。
- 按评估预算、sweep 上限或完整一轮无改进停止。
- 记录 K、扫描顺序、相位分辨率和缓存策略。初版称为 GABS 风格坐标搜索；未核对原论文全部细节前，不宣称严格复现某篇论文。
- GABS 的离散候选精度必须披露；另设统一相位量化实验，不能把低分辨率搜索结果解释成连续优化的公平上限。

### 2.4 SPSA `spsa`

每轮生成独立 Rademacher 扰动 `Delta_r ∈ {-1, +1}`：

```text
L_plus  = L(wrap(phi + c_k * Delta))
L_minus = L(wrap(phi - c_k * Delta))
g_hat_r = (L_plus - L_minus) / (2*c_k*Delta_r)
phi_next = wrap(phi - a_k*g_hat)
```

- 每次梯度估计只需两次损失评估，与相位维度无关。
- 记录学习率序列、扰动步长序列、随机种子及可选扰动平均次数。
- 若另外评估更新后的相位，其开销也必须计入；“两次评估”仅指一次梯度估计。
- 适合作为高维黑盒搜索和带噪声反馈的主要对照。

### 2.5 SAC 与 PPO

- 先使用成熟实现，例如 Stable-Baselines3 的 SAC/PPO，加 Gymnasium 环境适配，不自行重写核心 RL 算法。
- SAC 作为首个连续动作 RL 基线，PPO 作为第二种策略学习机制的补充。
- 固定场景实验记录从零训练的全部成本；预训练策略的测试性能另列，不能混为一张“优化耗时”表。
- 不因为某次 RL 训练失败就认定此类方法无效；超参数调优使用验证任务，保留失败与波动记录。

### 2.6 CMA-ES 与自身消融

- CMA-ES 后续采用成熟库，所有种群个体评估都计入预算；周期变量先优化未包裹的实数，再统一映射到相位。
- `ours_lbfgsb` 和 `ours_adam` 不复制现有优化器，只增加对统一评估和日志接口的适配。
- 自身消融包括相同初始化下的 Adam/L-BFGS-B，以及几何、零相位、响应对齐初始化。

```text
  __init__.py               算法注册、选项校验和调度

```

所有算法相关模块留在 `src/baselines/`；算法成熟后再按实际复杂度决定是否拆分子目录，不先构建通用插件系统。

### 与现有代码的边界

- [`phase_response_basis.py`](../src/training/phase_response_basis.py) 继续负责 G 构建、缓存、`field()` 和 `phase_vjp()`。
- [`phase_adjoint_optimizer.py`](../src/training/phase_adjoint_optimizer.py) 继续作为目标场、损失和当前优化器的实现来源，不另写一套不同公式。
- [`transducer_array.py`](../src/physics/transducer_array.py) 继续负责阵列几何与标定；几何相位和响应初始化的公共逻辑需要时做小范围提取。
- `baselines` 不实现新 Helmholtz 后端，不修改场景物理模型，不承担障碍物反演。
- SAC/PPO/CMA-ES 依赖按需导入；未安装 RL 依赖时，几何、GABS、SPSA 和现有求解流程仍应可用。
- `python src/main.py ...` 直接按顶层 `algorithm` 调度；`training.compare_geometric` 可额外输出几何相位对照场。

### 统一算法接口（拟定）

```text
solve(problem, initial_phases, budget, rng) -> BaselineResult
```

`problem` 提供网格、目标、阵列等必要任务描述和受控 evaluator。根据方法能力，仅开放它需要的信息：

| 方法组 | 可获得的接口 |
|---|---|
| 几何基线 | 阵元位置、目标位置、波数，以及最终评估 |
| 响应对齐 | 目标点复响应，以及最终评估 |
| GABS / SPSA / CMA-ES | 标量损失与统一报告指标，不访问 G 列或解析梯度 |
| SAC / PPO | `reset()` / `step()` 产生的公开观测和奖励，不返回解析梯度或直接暴露 G |
| 我们的方法 | 共享场评估与解析 VJP |

共用 G 作为模拟器不等于向所有优化算法提供 G 的内部数值。模型访问能力必须随实验结果一并说明。

`BaselineResult` 至少包含：

- `method`、`seed`、配置摘要和任务指纹。
- `final_phases`、`best_evaluated_phases`、对应损失和统一指标。
- `history`：累计场评估数、VJP 次数、时间、当前损失和 best-so-far。
- `termination_reason`、实际消耗预算和异常状态。
- RL 的训练步数、训练时间、策略检查点与测试交互次数。

当前优化器只返回最终相位；统一基准需额外记录最佳已评估候选，同时保留最终结果，不能只为某个方法选择最有利的历史点。

## 4. 共享损失与评估口径

第一轮主实验使用现有 `focal_contrast`：

```text
L = -alpha * mean(|u[target]|) + beta * smoothmax_T(|u[background]|)
```

后续增加 `field_match` 与多目标任务。所有方法在同一任务中使用相同损失、权重、温度、目标采样索引和背景掩码。

- 复用现有 loss，同时提供只计算标量损失的路径，避免无梯度方法被迫构造和丢弃 cotangent；用测试确认两条路径损失完全一致。
- 各 loss 的现有 `stats()` 定义不同，不能直接拼接其 `background_ref` 当统一指标。
- evaluator 独立定义所有方法共用的目标/背景区域和指标，优化损失与评估指标分别记录。
- 空背景掩码、非法目标、非有限损失和零分母要有明确处理；不能靠极小分母制造夸张对比度。

## 5. 公平实验协议

### 5.1 固定任务优化

- 首批参考场景为 [`phase_oblique_reflecting_x_12x12.yaml`](../src/examples/phase_oblique_reflecting_x_12x12.yaml)：12×12 阵列、0.12 m 求解域、41³ 网格、目标 `[0.09, 0.09, 0.09] m`、`+x` 反射。
- 该现有配置没有障碍物，不能将其作为“有障碍物”验证结果。
- 对照任务依次加入中心焦点、斜向开放边界、斜向反射边界、球体、侧向手部、多目标。
- 手部保持 `rotation_deg: [0.0, 90.0, 0.0]`；当前求解器最多一个障碍物。
- 迭代方法的主实验统一使用零相位或同一组预生成随机相位。现有示例的 `response` 初始化不自动成为所有比较的默认值。
- 公共响应对齐热启动另做消融，并明确初相位已利用模型信息。解析方法自身没有迭代初相位，不强行套用这一约束。
- 所有方法使用相同阵元数、固定幅值、网格、精度和评价区域。相位连续域与量化域实验分开报告。
- 随机方法初步至少 5 个种子；确定性解析基线不通过重复同一结果伪造样本量。
- 先给出性能随预算变化的曲线，再比较最终表格；预算与超参数调优范围在查看测试结果之前固定。

### 5.2 预算与时间

必须同时报告计算次数与墙钟时间，不把“一次迭代”视为共同单位。`compare.py` 为迭代算法设置统一 `60 s` 墙钟预算，可通过 `--max-seconds` 覆盖：

| 项目 | 计数原则 |
|---|---|
| `field_evaluations` | 每个候选相位合成一次场计一次，批处理按候选数计 |
| `vjp_evaluations` | 每次 G 的共轭转置乘法单独计数，不能视为免费 |
| `optimizer_iterations` | 仅作方法内部说明，不作为唯一公平预算 |
| 初始化、梯度检查、回调 | 若实际发生额外评估，均计入或单列，不能隐去 |
| RL `reset()`、rollout、验证 | 分训练、验证、测试记录所用场评估，不只记录网络更新次数 |
| 最终验证 | 固定的公共报告开销单列，不反馈给优化器选解 |

设场评估上限，并另做等时间比较。预算耗尽时返回已评估结果，不能返回尚未评估的更新候选。缓存命中同时记录请求次数、实际场合成次数与命中次数；缓存策略对方法一致。

时间分解：

```text
T_total = T_basis_build_or_load
        + T_pretrain_if_any
        + T_task_optimization_or_inference
        + T_reporting
```

- 分别给出包含 G 构建的冷启动和复用 G 的热启动结果。
- 同一 G 可以在评测进程中共享，但端到端成本表要说明共享与摊销方式。
- GPU 计时使用同步；记录后端、数据类型、设备与基准配置，不把 CPU/GPU 差异解释成算法差异。
- RL 更新网络的开销也进入时间统计。

### 5.3 强化学习训练后泛化

- 单独设置训练、验证和测试任务，不用测试结果挑选策略检查点或超参数。
- 先做固定场景下的目标位置泛化，再讨论跨障碍物、边界的场景泛化。
- 多目标或多场景扩展需要统一任务编码；若观测不足以区分场景，应明确部分可观测性，不能声称已具备通用策略。
- 对照包括逐任务运行的 GABS/SPSA/我们的优化器，以及已训练的 SAC/PPO 策略。
- 分别报告预训练成本、单任务推理、测试时交互/微调成本，以及任务数量增加后的摊销成本。
- 共用响应基的仿真比较主要衡量优化/控制方法；真实测量反馈实验属于后续独立协议。

## 6. RL 环境第一版约定

首版是固定场景、单目标、有限步数的相位调整环境：

| 项目 | 约定 |
|---|---|
| 观测 | `sin(phi)`、`cos(phi)`、归一化目标坐标、公开振幅统计、剩余步数比例 |
| 动作 | M 维连续动作 `a ∈ [-1, 1]^M` |
| 相位更新 | `phi_next = wrap(phi + delta_max*a)` |
| 转移 | 共用 evaluator 计算下一相位对应的场与损失 |
| 回合长度 | 固定 H 步或任务预算用尽；不因某个方法偶然达到指标就私自追加预算 |
| 评估策略 | 固定检查点，确定性推理，统一测试交互预算 |

首版奖励拟采用：

```text
r_t = (L(phi_t) - L(phi_(t+1))) / S
```

S 是仅由训练配置/训练任务确定的正尺度，不能依赖测试集或每个方法当前表现动态改变。

在有限回合、`gamma=1` 时奖励和等于 `(L_initial - L_final)/S`，与降低最终损失一致。回合时域结束应按该有限任务的终止语义处理，不误加终止后的价值。若改用 `gamma<1` 或逐步 `-L` 奖励，需要记录其目标变化并做消融，不能再声称严格等价于最终损失。

SAC 的熵正则、奖励尺度和网络训练超参数需显式记录。第一版不额外加入只针对 RL 的目标权重、动作降维或硬件约束；若引入，须给其他方法对应对照。

固定场景中，相位和目标已足以确定下一步物理响应；跨场景时必须重新审视观测设计。

## 7. 统一输出与指标

规划输出目录：

```text
outputs/baseline_comparison/<run_id>/
  manifest.json             任务、版本、配置、信息访问权限和种子
  summary.csv               每方法/任务/种子的最终与最佳指标
  aggregate.csv             均值、标准差、中位数和 P95 等聚合
  <task>/<method>/<seed>/
    result.npz              相位、最终场、最佳场和必要元数据
    history.csv             预算-损失-指标-时间轨迹
    metadata.json           超参数、终止原因和成本明细
    checkpoint.*            仅 RL 需要
```

指标至少包括：

- 所选损失及 best-so-far 损失。
- 目标点平均/最小振幅、背景最大振幅，以及统一 mask 下的焦点/旁瓣比。
- 多目标 `min/max` 均匀度和变异系数。
- `field_match` 的目标场相对 L2 误差；目标范数为零时改报绝对误差。
- 达到预先声明阈值的场评估数、时间和成功率；未达阈值的运行标记为未成功，不能从汇总剔除。
- 多种子和多任务统计；小样本 P95 仅作描述，不当作稳定尾部估计。
- 后续噪声/模型失配实验中的性能退化。

图表优先采用预算-损失曲线、时间-质量曲线、统一工作平面振幅图和相同绝对阈值的三维对照。各方法不能通过单独调整色标或阈值制造视觉优势。

## 9. 配置与运行入口安排

顶层 `algorithm` 和 `algorithm_options` 是单次运行的算法入口；共同参数保留在 `training`。当前运行方式：

```text
python src/main.py --config src/examples/config.yaml
```

固定场景的统一比较入口：

```text
python src/compare.py --config src/examples/phase_oblique_reflecting_x_12x12.yaml
```

它只构建/加载一次物理响应基，逐项写入 `outputs/algs/<scene>/<algorithm>/`，并生成 `summary.csv/json`。SAC、PPO、CMA-ES 的可选依赖单独列在 `src/baselines/requirements.txt`。
